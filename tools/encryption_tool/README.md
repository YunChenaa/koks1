# SenseLock AES 报文工具

这是一个基于 PySide6 的桌面工具，用于手工或批量分析锁端、模组端逻辑分析仪 CSV，并复现通信模块的 AES UART 报文加解密过程。

## 运行

```bash
python -m pip install -r tools/encryption_tool/requirements.txt
python tools/encryption_tool/main.py
```

运行全部测试：

```bash
python -m unittest discover -s tools/encryption_tool/tests -v
```

## 单条消息模式

单条消息页继续支持原有手工流程。

### 53 消息

输入完整明文 `MID_SET_DEBUG_ENC_KEY` 帧：

```text
EF AA | 53 | 00 10 | 16字节索引 | XOR
```

工具检查帧头、MID、长度和 XOR，并要求索引在 `0..31`。索引数组不是 AES 密钥。

### 50 消息

输入完整明文 `MID_INIT_ENCRYPTION` 帧。工具只使用 payload 前四个原始字节作为 seed，mode 不参与密钥派生。

会话密钥公式：

```text
H = lowercase_hex(MD5(seed 的 4 个原始字节))
K[i] = H[indexes[i]]
```

例如 seed `01 02 03 04` 和索引 `[6,18,7,3,13,13,23,4,8,1,0,25,9,2,2,7]` 得到：

```text
MD5: 08d6c05a21512a79a1dfeb9d2a8f262f
key: 5da6aadc280a1dda
```

### 待处理消息

加密模式输入完整明文 UART 帧：

```text
EF AA | MID | payload长度 | payload | XOR
```

输出完整 AES UART 帧：

```text
EF AA | 密文长度 | AES-128-ECB密文 | XOR(密文)
```

解密模式执行相反转换。AES 输入内文是 `MID + 长度字段 + payload`，不包含 `EF AA` 和外层 XOR。AES 使用 16 字节 ASCII 会话密钥、ECB 模式和零填充。

修改 53 或 50 输入后，旧密钥和结果立即失效，必须重新解析对应配置。勾选兼容选项后，可解密固件在整块内文后附加一个全零密文块的异常报文。

## CSV 批量分析

批量页需要选择两个文件：

- **锁端 CSV**：锁端下发到模组的字节，结果方向显示为 `锁端 → 模组`。
- **模组端 CSV**：模组返回锁端的字节，结果方向显示为 `模组 → 锁端`。

选择文件后，文件选择器下方的“索引信息”框会从两路 CSV 中最新的有效完整明文 `52` 或 `53` 消息提取 16 个索引，以十进制逗号分隔展示。无有效 `52/53` 时，该框留空；点击“分析 CSV”会提示填写索引。可直接修改框内值，批量分析始终以点击时框内的值为准，即使 CSV 本身含有 `52/53`。输入必须是 16 个 `0..31` 的十进制整数，以英文逗号分隔。文件路径变化会重新自动填充；“清空”会清空路径和索引。

每个文件按以下四列读取：

```text
时间,单字节十六进制,校验错误标志,帧格式错误标志
```

示例：

```csv
time,byte,checksum,frame
1.000,ef,,
1.001,aa,,
1.002,53,,
1.003,00,,
1.004,10,,
```

具体规则：

- 第一列用于排序，支持秒数、整数、`ms`、`us` 和 `ns` 后缀。无法解析的时间会使用行号作为稳定回退，并显示警告。
- 第二列支持 `ef`、`EF`、`0xEF`，每行必须是一个字节。
- 第三列为空表示未声明校验错误，非空表示该字节所属帧存在校验错误。此类帧仍会显示，但不会更新会话密钥，也不会进行可信解密。
- 第四列为 `error` 的字节一定会被丢弃，不会参与后续报文重组。
- 工具会先分别重组两个 CSV，不能跨文件拼接帧。两路重组完成后，再按照完整帧的起始时间合并。
- 报文通常从 `EF AA` 开始。明文长度字段位于第四、第五字节，AES 密文长度字段位于第三、第四字节，最后一个字节是 XOR 校验。
- 文件尾部没有收完整的帧时，会等待并忽略不完整尾帧，不把它伪装成完整消息。

### 会话密钥时间线

- 52 和 53 是明文索引控制帧，仅用于预填索引信息，结果表中仍显示原始报文，不当作 AES 帧解密。只有完整、XOR 正确且没有 CSV 校验错误标志的 16 字节索引（每项 `0..31`）才会被采用。
- 批量分析固定使用索引信息框中的值；遇到另一条 52/53 不会覆盖用户输入。
- 每一个有效完整的 50 消息使用自身前四字节 seed 和框内索引生成新的会话密钥。后续 AES 帧只使用时间上最近一次有效 50 生成的密钥，不会用最后一个 seed 解整个文件。
- 多次上下电产生多个 50 时，每段 AES 报文会显示采用的 `50@时间` 来源。缺少有效 50 时无法解密。没有 52/53 也可手动填写索引后正常分析。

### 结果和 MID 状态

结果表按序号、时间、锁端到模组、模组到锁端、帧类型、MID、解密或明文报文、原始报文、校验状态、密钥来源和诊断的顺序展示。锁端到模组列只显示加粗绿色右箭头 `→`，模组到锁端列只显示加粗红色左箭头 `←`，另一方向列保持为空。MID 列使用 `MID名称;两位十六进制代码;结果或状态`，例如 `MID_REPLY;00;SUCCESS` 和 `MID_NOTE;01;FACE_STATE_NOFACE`。回复 payload 第二字节为零时标记 `SUCCESS`，非零时标记 `FAIL`；note 的 NID 为零时标记 `ready`。面部和手掌状态名称取自对应的 `FACE_STATE_*`、`PALM_STATE_*` 常量，结构中的状态是小端 16 位有符号整数。NID 04 和 08 在不同编译配置中可能分别指眼睛/手掌或授权/手掌；数据长度不足或状态不存在时只显示原始状态值，不误判成具体手掌状态。

输出表格上方提供可横向滚动、可放大或缩小的收发时间轴。每条完整消息按帧起始时间绘制一个圆点：蓝色表示锁端到模组端，MID 十六进制数字标在圆点上方；红色表示模组端到锁端，数字标在下方。时间刻度紧贴标尺显示，节点连线采用短线段。点的位置按真实时间间隔计算，时间相同或密集时标签错层排列，不人为挪动时间点。悬停可查看方向、原始时间、MID、校验状态和对应行号；点击圆点或 MID 标签会选中并滚动到表格对应行，同时显示完整详情。无法解析的时间会在独立的“时间无效”区域按顺序排列，不作为真实时间间隔。清空结果也会清空时间轴。

批量分析页整体可上下滚动，适配窗口高度不足的场景。输出表格设有至少十行的可见高度；当页面内容超过窗口时，使用页面纵向滚动条查看完整内容。

锁端到模组端的表格方向标为绿色，模组端到锁端的表格方向标为红色，方向文字加粗。选中一行可在详情区复制完整报文。点击“保存输出表格”可把当前完整结果保存为 UTF-8 BOM 编码的 CSV，表格和导出使用相同的 MID 状态格式。

工具运行时从 `application/communication/include/message_l.h` 和 `application/communication/include/message_v2.h` 读取 MID 名称和状态常量。头文件不可用时保留 50、52、53 的内置名称；未知 MID 显示为 `UNKNOWN_0xHH;HH`，不会凭空补写状态。

## 限制

- 当前工具只实现 AES 路径，不实现 C++ 中的 SMPL 简单加密路径。
- XOR 和解密后结构检查不提供密码学认证，不能保证发现所有错误密钥或篡改。
- 工具只读取和分析 CSV，不连接设备，不发送报文。
- 批量解析错误会保留在界面诊断中，不会让整个文件因单行坏数据直接退出。
